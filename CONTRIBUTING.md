# Contributing to Grom Synthetic BR

Thank you for helping improve an open, reproducible Brazilian research resource.

## Contribution principles

Contributions should preserve the project's core values: reproducibility, traceability, licensing clarity, deterministic behavior and separation between normative evidence and engineering assumptions.

## Before submitting a change

Please:

1. explain the problem being addressed;
2. describe the method used;
3. identify any external source, dataset, font, model or image involved;
4. document licensing and provenance;
5. add or update tests when behavior changes;
6. avoid silently changing canonical geometry, baselines or validation policy;
7. state limitations and unresolved uncertainty.

## High-review changes

The following require especially careful review:

- canonical geometry or rendering changes;
- normative interpretations;
- new font or asset adoption;
- dataset-generation policy;
- baseline promotion;
- changes that alter confused-pair behavior or spatial-fit rules;
- changes that affect reproducibility or provenance.

## Licensing and provenance

Do not contribute material unless you have the right to do so.

Third-party assets must include enough information to evaluate:

- source;
- author or provider;
- license;
- redistribution rights;
- modification rights, when relevant;
- provenance and integrity information.

"Free download" and "freeware" are not automatically equivalent to open-source redistribution permission.

## Data and privacy

Do not submit personal data, confidential records, credentials, private keys, restricted datasets or material whose publication rights are uncertain.

## Reciprocity

The Apache License 2.0 does not require every derivative work to be published. Even so, contributors and users are strongly encouraged to return useful improvements to the community through:

- bug reports;
- reproducible benchmarks;
- documentation;
- corrected assumptions;
- tests;
- new research evidence;
- pull requests.

If the project supports an academic publication, please cite the repository and identify the version or commit used.

## Pull requests

A good pull request should contain:

- a concise rationale;
- the affected research or engineering assumption;
- test evidence;
- provenance/licensing notes when relevant;
- a statement that no unrelated baseline, dataset or external asset was silently changed.

By contributing code to this repository, you agree that your contribution is provided under the repository's Apache License 2.0 unless explicitly documented otherwise for a non-code contribution.
